## 改动 1/4　§3 新增「命令级止损」与调用约定（dsh 职责）

**现状（v2.1 §3「超时闸门」）**

> 【v2.1】实测结论：`timeoutMs` 到点不 kill 进程……真正的止损只能由 Hermes 侧 `task_cancel` 完成。

**改为（v2.2）**

【v2.2】**两层止损，职责分开**：

- **命令级（dsh 职责）**：可能超过 60s 的每条命令、以及所有 long-run，必须用 `_tools/run-with-timeout.ps1` 包住；到时 kill 子进程树（含孙进程），不再依赖 `timeoutMs` 的“到点”假象。
- **任务级（Hermes 职责）**：`task_cancel` 只兜底“dsh 整体不响应”（见改动 2）。单条命令卡死应在命令级结束，不得拖到看门狗。

**调用约定**（必须原样执行；`-Command` 用单引号包住，命令内部的双引号写成两个双引号）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File _tools\run-with-timeout.ps1 `
  -Command 'node -e ""setTimeout(function(){},60000)""' `
  -TimeoutSec 300 `
  -OutFile _evidence\longrun-1.json
```

命令自带多层引号时，先把命令写进 `_tools\cmd-*.ps1`，再用 `-Command '& .\_tools\cmd-xxx.ps1'`，避免引号被二次解释。

脚本行为（唯一契约）：

- 参数：`-Command`（必填）、`-TimeoutSec`（必填，可为小数）、`-OutFile`（结果 JSON 路径，可选）。
- 超时：kill 子进程树，stdout 最后一行 `{"killed":true,"elapsed_s":N}`，wrapper 退出码 **124**。
- 正常：stdout 最后一行 `{"killed":false,"elapsed_s":N,"exit_code":N}`，wrapper 退出码 = 子命令退出码。
- `-OutFile` 写同一行 JSON，**UTF-8 无 BOM**；子命令 stdout/stderr 原样转发。
- 脚本由 dsh 每任务在 `_tools/` 重建（参考实现即本任务产物）；交付前删除，不依赖全局安装。

**环境注记（本机实测）**：没有 pwsh 7，只有 Windows PowerShell 5.1（`5.1.26100.9711`）；沙箱内 `taskkill /T` 与 WMI/CIM 均 `Access denied`，故参考实现用 Toolhelp32 快照枚举子孙 PID + `Stop-Process`。调用方只需遵守上面的 JSON/退出码契约，不必关心实现。

**为什么写进契约**：实现不写调用约定，下次 dsh 仍会直接跑裸命令；调用约定不配实现，下次仍无脚本可用。两者同版发布。

## 改动 2/4　§3 看门狗缩放 + 标注待验证

**现状（v2.1 §3）**

> 每 5 分钟检查两个指标……两者都超过 8 分钟无变化才 `task_cancel`。

**改为（v2.2）**

【v2.2】**看门狗参数随预算缩放**：

- 检查间隔 = `min(5min, 预算/3)`
- 静默阈值 = `min(8min, 预算/3)`
- lite（预算 15min）：间隔 5min / 阈值 5min；30min 任务：间隔 5min / 阈值 8min（上限不变）。
- 判据仍是双指标：目标目录 mtime 与 `session_log` 最后事件时间**都**超过阈值才 `task_cancel`。
- 定位：看门狗只兜底“dsh 连 pwsh 都起不来 / 整体不响应”；单条命令卡死由改动 1 在命令级处理，不应走到这里。

【v2.2 **待验证**】本参数尚未在真实卡死中校准。校准方法：首次真实卡死时记录「最后事件时间 → cancel 实际间隔」，把实测值回填本节，并把“待验证”改为实测结论。若实际间隔 > 阈值 × 2，说明检查粒度或事件源失真，下版调整（不是加严阈值掩盖）。
